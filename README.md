# Семейный Тайный Санта — 2027

Русскоязычное семейное приложение: каждый заполняет пожелания, организатор проверяет состав и запускает секретную жеребьёвку. Каждый дарит одному человеку и получает подарок от одного; назначить самого себя нельзя. Организатор видит все назначения.

**Статус:** полноценная локальная версия с новогодним оформлением и персональными мультяшными портретами. Публичная семейная ссылка ещё не опубликована. Публикация через Sites пока недоступна: в текущем окружении отсутствуют обязательные lifecycle helpers плагина. Для самостоятельного размещения подготовлен Dockerfile.

- Бюджет: **50–100 долларов США**.
- Карточки заполняют до конца **25 декабря 2026 года по Ташкенту** (`Asia/Tashkent`, UTC+5). Сервер закрывает приём **26 декабря в 00:00**, то есть `2026-12-25T19:00:00Z`.
- Вручение подарков: **1 января 2027 года**.
- Подробные требования: [docs/CONCEPT.md](docs/CONCEPT.md).

## Локальный запуск

Нужен **Node.js 24 или новее** с поддержкой встроенного `node:sqlite`. Внешних зависимостей нет; `npm install` не требуется.

```sh
npm start
```

Откройте `http://localhost:3000`. После первого запуска в другом терминале получите ссылки:

```sh
npm run access
```

Команда читает созданный сервером `data/access.json` и явно выводит личную ссылку организатора и общее приглашение. Обычный запуск сервера не выводит эти секреты. `localhost` доступен только на текущем компьютере; такая ссылка ещё не подходит для семейного чата.

### Как участвовать

1. Организатор сохраняет свою ссылку и отправляет семье **общую ссылку приглашения**.
2. Каждый открывает приглашение и выбирает себя среди именных мультяшных портретов. Открывается персональная анкета с портретом: пожелания, ссылки на подарки и нежелательные подарки. Без настроенного списка профилей имя вводится вручную.
3. Участник сохраняет **личную ссылку**, которую выдаёт приложение. Браузер также запоминает доступ на этом устройстве. На другом устройстве или после очистки данных браузера понадобится сохранённая ссылка.
4. Организатор проверяет карточки, подтверждает участников, удаляет дубли и при необходимости добавляет людей сам.
5. После завершения приёма организатор вручную запускает жеребьёвку. Участники видят только своего получателя, организатор — полную таблицу.

Личные ссылки дают доступ к соответствующей карточке; ссылку организатора храните отдельно от семейного приглашения. При потере личной ссылки организатор может перевыпустить доступ. Изменение состава после жеребьёвки требует отдельной отмены распределения: прежние результаты перестают действовать для всех, затем организатор проводит новую жеребьёвку. Повторное открытие редактирования пожеланий не меняет назначения.

Портрет с уже созданной карточкой помечается занятым. Выбор имени не открывает чужую анкету: для возвращения к своей карточке нужна личная ссылка. Организатор может добавлять участников вне списка портретов; при совпадении имени со свободным профилем портрет привязывается автоматически.

## Настройки

Переменные задаются в окружении процесса; приложение не загружает `.env` автоматически.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | Порт HTTP-сервера |
| `HOST` | `127.0.0.1` | Адрес прослушивания; в Docker — `0.0.0.0` |
| `DATA_DIR` | `./data` | Постоянная папка базы, ключей доступа, семейного портрета и списка профилей |
| `APP_URL` | `http://localhost:3000` либо `http://localhost:PORT` | Точный внешний origin: протокол, домен и при необходимости порт; без пути, параметров и фрагмента |
| `NODE_ENV` | окружение запуска | При `production` требуется HTTPS-значение `APP_URL` |

У `npm start` и `npm run access` должны быть одинаковые `DATA_DIR`, `PORT` и `APP_URL`. Персональные ключи создаёт сервер; в исходниках или примерах конфигурации их нет.

Семейный портрет хранится в **`DATA_DIR/family-portrait.png`**, имена и настройки портретов — в **`DATA_DIR/family-profiles.json`**. Папка данных и фотография исключены из Git и Docker image. Их нужно переносить отдельно на сервер, с закрытыми правами доступа. Для каталога данных используются права `0700`, для файлов — `0600`. Общий зимний фон `public/winter-scene.webp` не содержит семейных данных и входит в исходники.

### Именные портреты

Необязательный файл `DATA_DIR/family-profiles.json` включает выбор участника по портрету. Без него остаётся обычная анкета с ручным вводом имени. В репозитории есть [пример с вымышленными профилями](docs/family-profiles.example.json); настоящие имена остаются только в закрытой папке данных.

Формат файла — JSON-массив объектов:

| Поле | Значение |
| --- | --- |
| `id` | Постоянный уникальный идентификатор: 1–40 строчных латинских букв, цифр или дефисов |
| `name` | Уникальное отображаемое имя, до 60 символов; регистр и лишние пробелы не различают участников |
| `role` | Необязательная по смыслу подпись, до 60 символов; поле обязательно, допустима пустая строка |
| `crop` | `[x, y, width, height]`: прямоугольник портрета в пикселях общего изображения **1536 × 1024** |

Для `crop` используйте конечные неотрицательные числа и положительные ширину и высоту; прямоугольник должен целиком помещаться в изображение. Координаты в примере условные: подберите их под своё изображение. После изменения файла перезапустите приложение. Не меняйте `id` профиля, к которому уже привязана карточка.

Аватары отображаются через SVG с заданной областью общего портрета. Изображение загружается из защищённого `/api/photo`; отдельных общедоступных файлов лиц нет. Список профилей виден только посетителям с приглашением, личным доступом или доступом организатора. Без доступа список пуст. При обновлении старой базы приложение автоматически добавляет `profile_id` и переводит схему с версии 1 на 2, сохраняя карточки, доступы и назначения.

## Размещение с Docker

Нужны сервер с Docker, домен и HTTPS-прокси, который передаёт запросы приложению. Укажите свой реальный HTTPS-адрес вместо примера:

```sh
docker build -t family-secret-santa .
docker volume create secret-santa-data
docker run -d --name secret-santa --restart unless-stopped \
  -p 127.0.0.1:3000:3000 \
  -e APP_URL=https://santa.example.com \
  -v secret-santa-data:/app/data \
  family-secret-santa
```

Настройте HTTPS-прокси для этого домена на `127.0.0.1:3000`. Затем **на своём терминале** получите готовые ссылки:

```sh
docker exec secret-santa npm run access
```

Скопируйте портрет и закрытый список профилей в постоянный том, установите владельца и права, затем перезапустите приложение. Если используете ручной ввод имён, файл профилей не требуется:

```sh
docker cp ./data/family-portrait.png secret-santa:/app/data/family-portrait.png
docker cp ./data/family-profiles.json secret-santa:/app/data/family-profiles.json
docker exec -u root secret-santa chown node:node /app/data/family-portrait.png /app/data/family-profiles.json
docker exec -u root secret-santa chmod 600 /app/data/family-portrait.png /app/data/family-profiles.json
docker restart secret-santa
```

Контейнер работает от пользователя `node`. При использовании собственной папки хоста вместо именованного тома заранее разрешите этому пользователю запись в неё. Том нужно сохранять при обновлении контейнера: без него будут утрачены карточки, результаты и доступы. Проверка готовности сервера: `GET /healthz`; в образ включён healthcheck.

### Резервные копии

Сохраняйте **всю папку `DATA_DIR` целиком**: базу SQLite с сопутствующими файлами, `access.json`, фотографию и `family-profiles.json`, если он настроен. Для согласованной копии остановите приложение, скопируйте папку или том, затем снова запустите его. Восстанавливайте всё вместе, сохраняя владельца и закрытые права доступа. Резервная копия содержит личные данные и секреты; храните её в защищённом месте вне публичного репозитория.
