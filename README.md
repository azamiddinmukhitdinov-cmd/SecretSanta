# Семейный Тайный Санта — 2027

## [🎄 Открыть сайт Secret Santa](https://pc.taileea726.ts.net/)

### [🔑 Кабинет организатора](https://pc.taileea726.ts.net/#organizer)

Здесь можно управлять участниками, приглашениями и жеребьёвкой с телефона или компьютера. При первом входе вставьте свою личную ссылку организатора из чата. Браузер запоминает доступ на 30 дней. Кнопка открывает кабинет сразу, если вы уже вошли.

Ссылка работает и на телефоне. Для первого входа откройте своё личное приглашение или ссылку организатора в том же браузере, затем сохраните сайт в закладках. Закрытые ссылки организатора и участников передаются лично.

Сайт работает на компьютере организатора: он должен быть включён, подключён к интернету и не переходить в сон.

Русскоязычное семейное приложение: каждый заполняет пожелания, организатор проверяет состав и запускает секретную жеребьёвку. Каждый дарит одному человеку и получает подарок от одного; назначить самого себя нельзя. Организатор видит все назначения.

**Статус:** рабочая версия с новогодним оформлением, интерактивным семейным портретом, анкетами, личными приглашениями и секретной жеребьёвкой. Приложение можно разместить на домашнем компьютере с HTTPS-туннелем или на сервере; для контейнерного размещения есть Dockerfile.

- Бюджет: **50–100 долларов США**.
- Жеребьёвка — **22 ноября 2026 года по Ташкенту**: организатор запускает её вручную начиная с 00:00 этой даты. Все участники должны быть добавлены и подтверждены; незаполненные пожелания не мешают распределению.
- Пожелания впервые заполняют до конца **6 декабря 2026 года по Ташкенту** (`Asia/Tashkent`, UTC+5). Срок заканчивается **7 декабря в 00:00**, то есть `2026-12-06T19:00:00Z`. Исправлять пожелания можно и позже, пока организатор не закрыл редактирование.
- Вручение подарков: **1 января 2027 года**.
- Подробные требования: [docs/CONCEPT.md](docs/CONCEPT.md).

## Что нового для семьи

- На семейном портрете можно нажать на своего персонажа и перейти к письму. Выбор по именным карточкам также сохранён. Занятые профили не открывают чужие анкеты.
- До 1 января идёт отсчёт по Ташкенту. Приглашённым участникам виден общий счётчик отправленных писем без чужих пожеланий.
- Подсказки «Для уюта», «Для хобби» и «Впечатления» добавляют примеры в пожелания; их можно свободно исправить. Отправленное письмо получает отметку «Доставлено».
- После жеребьёвки появляется личная мастерская: «Подарок выбран — сообщить получателю», «Купил или сделал», «Упаковал». Первая отметка после отдельного подтверждения отправляет получателю анонимную новость о выборе подарка. Остальные отметки доступны только дарителю. При отмене жеребьёвки они очищаются.
- Организатор может подготовить все недостающие личные приглашения одним действием, скопировать отдельные сообщения и скачать их файлом. Действующие ссылки не меняются, сообщения автоматически не отправляются. Подготовленные ссылки доступны в текущем сеансе страницы; скачайте файл перед её закрытием и передавайте каждому только его сообщение.

## Локальный запуск

### Сохранность писем и уведомления

- Черновик сохраняется в браузере при вводе и восстанавливается после закрытия страницы, когда сайт снова доступен. Он привязан к карточке участника или выбранному профилю, хранится до 30 дней и удаляется после успешной отправки или явного выхода. Это локальная копия: на другом устройстве её нет, а очистка данных браузера удалит её. Если браузер запрещает локальное хранение, сайт покажет предупреждение.
- Каждое сохранение карточки передаёт её идентификатор и прочитанную версию. Другие участники сохраняют свои карточки независимо. При двух редакторах одной карточки устаревшее сохранение отклоняется; черновик остаётся, интерфейс предлагает сравнить варианты. Вход по другой личной ссылке в соседней вкладке также не позволяет записать письмо под чужим именем.
- Сайт автоматически создаёт согласованную копию SQLite и корневых файлов данных раз в 7 дней, проверяя срок при запуске и раз в час. По умолчанию папка — `backups/weekly` рядом с исходниками; можно задать `BACKUP_DIR`. После простоя пропущенная копия создаётся при следующем запуске. Каждая завершённая копия содержит `manifest.json` с датой и контрольными суммами. Автоматическое удаление копий не включено. Копии содержат приватные ключи и настройки почты: не публикуйте их и периодически переносите копию на другой носитель.
- На сайте есть личные новости о пожеланиях получателя и анонимная новость о выборе подарка вашим Сантой. Для почты участник сам указывает адрес, включает согласие и подтверждает адрес ссылкой из письма (действует сутки). Адрес не виден другим участникам и не включён в карточку получателя.
- Организатор один раз подключает отправителя в кабинете: Gmail, Яндекс или Mail.ru и пароль приложения. Для Gmail нужна двухэтапная аутентификация. Настройки сохраняются только в закрытом `data/mail.json`; пароль не возвращается интерфейсу. До подключения сайт честно показывает, что отправка не настроена. Обработчик проверяет очередь раз в минуту, при сбое повторяет попытку через 5 минут, максимум 5 попыток. Неудачные доставки видны участнику в настройках почты; после пяти попыток можно повторно запросить подтверждение. Доставка реальным провайдером зависит от настроек ящика и фильтров получателя.

Для восстановления остановите сайт, выберите завершённую копию, проверьте контрольные суммы из `manifest.json` и восстановите `santa.sqlite` вместе с `access.json`, семейными файлами и конфигурацией. Старые `santa.sqlite-wal` и `santa.sqlite-shm` не должны остаться от другой базы. Сохраните текущую папку данных отдельно до замены. Запустите сайт и проверьте личный доступ и назначения. Резервная копия на том же диске не защищает от поломки диска.

### Установка

Нужен **Node.js 24 или новее** с поддержкой встроенного `node:sqlite`. Для отправки почты используется Nodemailer. Установите зависимости командой `pnpm install --frozen-lockfile --ignore-scripts` (lockfile включён в репозиторий); при использовании npm можно выполнить `npm install --ignore-scripts`.

```sh
npm start
```

Откройте `http://localhost:3000`. После первого запуска в другом терминале получите ссылки:

```sh
npm run access
```

Команда читает созданный сервером `data/access.json` и явно выводит личную ссылку организатора и общее приглашение. Обычный запуск сервера не выводит эти секреты. `localhost` доступен только на текущем компьютере; такая ссылка ещё не подходит для семейного чата.

### Как участвовать

1. Организатор сохраняет свою ссылку и отправляет семье **общую ссылку приглашения**.
2. Каждый открывает приглашение и выбирает себя среди именных мультяшных портретов. Открывается персональная анкета с портретом: пожелания, ссылки на подарки и нежелательные подарки. Без настроенного списка профилей имя вводится вручную.
3. Участник сохраняет **личную ссылку**, которую выдаёт приложение. Браузер также запоминает доступ на этом устройстве. На другом устройстве или после очистки данных браузера понадобится сохранённая ссылка.
4. Организатор проверяет карточки, подтверждает участников, удаляет дубли и при необходимости добавляет людей сам.
5. Организатор заранее создаёт карточки всех участников и подтверждает состав, затем **22 ноября** вручную запускает жеребьёвку. Готовность пожеланий не обязательна. Участники видят своего получателя; если тот ещё не отправил письмо, отображается ожидание до 6 декабря. По готовности письма Санта получает уведомление. Организатор видит полную таблицу назначений.
6. Если пожелания изменились, участник открывает свою личную ссылку, нажимает **«Изменить пожелания»** и сохраняет письмо. Можно обновить пожелания, нежелательные подарки и ссылки даже после жеребьёвки. Санта увидит актуальную карточку при обновлении страницы; назначения сохраняются. Организатор при необходимости может закрыть редактирование переключателем в кабинете.

Личные ссылки дают доступ к соответствующей карточке; ссылку организатора храните отдельно от семейного приглашения. При потере личной ссылки организатор может перевыпустить доступ. Изменение состава после жеребьёвки требует отдельной отмены распределения: прежние результаты перестают действовать для всех, затем организатор проводит новую жеребьёвку. Повторное открытие редактирования пожеланий не меняет назначения.

Портрет с уже созданной карточкой помечается занятым. Выбор имени не открывает чужую анкету: для возвращения к своей карточке нужна личная ссылка. Организатор может добавлять участников вне списка портретов; при совпадении имени со свободным профилем портрет привязывается автоматически.

### Личные приглашения от организатора

В кабинете организатора возле свободного семейного профиля нажмите **«Создать личную ссылку»**. Приложение создаст черновик карточки (`ready: false`) и выдаст ссылку именно этого участника. Её можно отправить человеку напрямую: он сразу откроет свою анкету с портретом, заполнит пожелания и сохранит их. Создание ссылки ещё не означает, что анкета заполнена.

Кнопка **«Поделиться»** у сохранённой ссылки открывает системное меню отправки; если оно недоступно, ссылка копируется. Сообщение отправляет сам пользователь. **«Новая ссылка»** требует подтверждения и отзывает прежний доступ: после перевыпуска участнику нужно отправить новую ссылку.

## Настройки

Переменные задаются в окружении процесса; приложение не загружает `.env` автоматически.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | Порт HTTP-сервера |
| `HOST` | `127.0.0.1` | Адрес прослушивания; в Docker — `0.0.0.0` |
| `DATA_DIR` | `./data` | Постоянная папка базы, ключей доступа, семейного портрета и списка профилей |
| `APP_URL` | `http://localhost:3000` либо `http://localhost:PORT` | Точный внешний origin: протокол, домен и при необходимости порт; без пути, параметров и фрагмента |
| `NODE_ENV` | окружение запуска | При `production` требуется HTTPS-значение `APP_URL` |

У `npm start` и `npm run access` должны быть одинаковые `DATA_DIR`, `PORT` и `APP_URL`. Персональные ключи создаёт сервер; в исходниках или примерах конфигурации их нет.

Семейный портрет хранится в **`DATA_DIR/family-portrait.png`**, имена и настройки портретов — в **`DATA_DIR/family-profiles.json`**. Папка данных и фотография исключены из Git и Docker image. Их нужно переносить отдельно на сервер, с закрытыми правами доступа. На Linux и macOS для каталога данных используются права `0700`, для файлов — `0600`; на Windows доступ к папке задаётся разрешениями Windows. Общий зимний фон `public/winter-scene.webp` не содержит семейных данных и входит в исходники.

### Именные портреты

Необязательный файл `DATA_DIR/family-profiles.json` включает выбор участника по портрету. Без него остаётся обычная анкета с ручным вводом имени. В репозитории есть [пример с вымышленными профилями](docs/family-profiles.example.json); настоящие имена остаются только в закрытой папке данных.

Формат файла — JSON-массив объектов:

| Поле | Значение |
| --- | --- |
| `id` | Постоянный уникальный идентификатор: 1–40 строчных латинских букв, цифр или дефисов |
| `name` | Уникальное отображаемое имя, до 60 символов; регистр и лишние пробелы не различают участников |
| `role` | Необязательная по смыслу подпись, до 60 символов; поле обязательно, допустима пустая строка |
| `crop` | `[x, y, width, height]`: прямоугольник портрета в пикселях общего изображения **1536 × 1024** |

Для `crop` используйте конечные неотрицательные числа и положительные ширину и высоту; прямоугольник должен целиком помещаться в изображение. Координаты в примере условные: подберите их под своё изображение. После изменения файла перезапустите приложение. Не меняйте `id` профиля, к которому уже привязана карточка.

Аватары отображаются через SVG с заданной областью общего портрета. Изображение загружается из защищённого `/api/photo`; отдельных общедоступных файлов лиц нет. Список профилей виден только посетителям с приглашением, личным доступом или доступом организатора. Без доступа список пуст. Приложение обновляет старые базы до схемы 5: добавляет `profile_id`, если его ещё нет, и отдельную таблицу личных отметок мастерской, сохраняя карточки, доступы и назначения.

## Из GitHub в работающий сайт

GitHub хранит код. **GitHub Pages не запускает этот Node.js-сервер и SQLite**, поэтому для общих семейных данных нужен работающий сервер. Им может быть домашний компьютер организатора.

### На компьютере организатора

Схема доступа: **семейный браузер → постоянный HTTPS-адрес → туннель → приложение на PC → локальная SQLite**. Участникам нужен только браузер. Компьютер должен оставаться включённым, не переходить в сон и иметь интернет.

Порядок настройки и команды для Windows, macOS и Linux: [docs/PC-HOSTING.md](docs/PC-HOSTING.md). Доступ к папке позволяет перенести исходники, но сам по себе не запускает сервер и не создаёт внешний адрес. Для настройки на PC команды нужно выполнять именно на этом компьютере.

Для внешнего хостинга Dockerfile можно использовать с постоянным томом, корректным `APP_URL` и HTTPS-прокси. Каталог данных должен быть доступен пользователю контейнера `node` (UID `1000`); контейнер не меняет владельца подключённого тома при старте.

## Размещение с Docker

Нужны сервер с Docker, домен и HTTPS-прокси, который передаёт запросы приложению. Укажите свой реальный HTTPS-адрес вместо примера:

```sh
docker build -t family-secret-santa .
docker volume create secret-santa-data
docker run -d --name secret-santa --restart unless-stopped \
  -p 127.0.0.1:3000:3000 \
  -e APP_URL=https://santa.example.com \
  -v secret-santa-data:/app/data \
  family-secret-santa
```

Настройте HTTPS-прокси для этого домена на `127.0.0.1:3000`. Затем **на своём терминале** получите готовые ссылки:

```sh
docker exec secret-santa npm run access
```

Скопируйте портрет и закрытый список профилей в постоянный том, установите владельца и права, затем перезапустите приложение. Если используете ручной ввод имён, файл профилей не требуется:

```sh
docker cp ./data/family-portrait.png secret-santa:/app/data/family-portrait.png
docker cp ./data/family-profiles.json secret-santa:/app/data/family-profiles.json
docker exec -u root secret-santa chown node:node /app/data/family-portrait.png /app/data/family-profiles.json
docker exec -u root secret-santa chmod 600 /app/data/family-portrait.png /app/data/family-profiles.json
docker restart secret-santa
```

HTTP-сервер с самого старта работает от пользователя `node` (UID `1000`). Новый именованный Docker-том наследует подготовленные права каталога из образа. Уже существующий том или собственную папку хоста нужно заранее подготовить для UID `1000`, с правами `0700` для каталога и `0600` для файлов: автоматического сброса прав или исправления владельца при старте нет. Том нужно сохранять при обновлении контейнера: без него будут утрачены карточки, результаты и доступы. Проверка готовности сервера: `GET /healthz`; в образ включён healthcheck.

### Резервные копии

Сохраняйте **всю папку `DATA_DIR` целиком**: базу SQLite с сопутствующими файлами, `access.json`, фотографию и `family-profiles.json`, если он настроен. Для согласованной копии остановите приложение, скопируйте папку или том, затем снова запустите его. Восстанавливайте всё вместе, сохраняя владельца и закрытые права доступа. Резервная копия содержит личные данные и секреты; храните её в защищённом месте вне публичного репозитория.
