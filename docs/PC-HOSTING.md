# Сайт на компьютере организатора

Сервер хранит анкеты, доступы и результаты в папке `data` на компьютере организатора. Семья открывает сайт по HTTPS-ссылке в обычном браузере. Чтобы сайт работал, нужны запущенное приложение, интернет и внешний HTTPS-адрес. Прямое подключение к этому компьютеру не входит в доступ к облачной рабочей папке разработки.

## 1. Проверить локальный запуск

Установите [Node.js 24 LTS](https://nodejs.org/), скачайте ветку `main` этого репозитория и откройте терминал в папке с `package.json`. Внешних зависимостей нет; `npm install` не нужен.

Семейные файлы переносятся отдельно в `data/family-portrait.png` и `data/family-profiles.json`. В публичном репозитории их нет. Без них можно проверить работу сайта с ручным вводом имён.

**Быстрый запуск на Windows:** откройте `start-windows.cmd` двойным щелчком и оставьте окно открытым. Затем откройте `access-windows.cmd`, чтобы получить ссылки организатора и общего приглашения. Файлы запуска работают из папки проекта независимо от текущей папки терминала. Они используют установленный `node.exe`, а при его отсутствии — встроенный Node.js приложения Codex, если он доступен. Отдельный `npm` не требуется. Если сервер уже запущен, второй экземпляр запускать не нужно.

```sh
npm start
```

Откройте `http://localhost:3000`; `http://localhost:3000/healthz` должен вернуть `{"ok":true}`. В другом терминале, в той же папке:

```sh
npm run access
```

Ссылка организатора предназначена только для него. Адрес с `localhost` работает только на этом компьютере; отправлять его семье пока рано. Для остановки сервера нажмите `Ctrl+C` в первом терминале.

## 2. Настроить постоянный HTTPS-адрес

### Без покупки домена: Tailscale Funnel

Для личного семейного проекта можно использовать бесплатный тариф Tailscale Personal и Funnel. Внешний адрес имеет вид `https://имя-компьютера.имя-сети.ts.net`. Родственникам не нужны аккаунты и приложение Tailscale. Funnel находится в beta и имеет ограничения пропускной способности.

1. Установите Tailscale на PC и войдите в личный аккаунт. Официальная загрузка: https://tailscale.com/download/windows .
2. Сначала получите доменное имя этого устройства из `tailscale status --json` (поле `Self.DNSName`). Сформируйте точный HTTPS-origin без завершающей точки DNS.
3. Перед публикацией сохраните этот адрес в закрытом `data/hosting.json`:

   ```json
   { "appUrl": "https://your-computer.your-tailnet.ts.net", "port": 3000 }
   ```

   Адрес выше — пример, замените его реальным адресом своего устройства. `start-windows.cmd` и `access-windows.cmd` читают этот файл и используют одинаковые настройки. Если файл отсутствует, сохраняется обычный локальный запуск. При настроенном HTTPS используйте внешний адрес и для входа организатора.

4. Перезапустите приложение через `start-windows.cmd`. Затем включите только проксирование приложения командой `tailscale funnel --bg http://127.0.0.1:3000`. При первом включении Tailscale выдаёт страницу подтверждения Funnel и HTTPS.
5. Проверьте внешний `/healthz` и вход по приглашению с мобильного интернета. Только после проверки отправляйте ссылки семье.

Параметр `--bg` сохраняет Funnel после перезапуска службы или компьютера. На Windows для работы без входа в сеанс нужен режим Tailscale Run unattended; автозапуск Node.js настраивается отдельно. Переименование устройства или сети меняет адрес — обновите конфигурацию и приглашения. Для отключения этого прокси используйте `tailscale funnel --https=443 off`.

После проверки HTTPS и разрешения организатора на постоянный автозапуск откройте PowerShell с правами администратора в папке проекта и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\install-windows-autostart.ps1 -EnableTailscaleUnattended
```

`RemoteSigned` действует только в этом процессе, системная политика не меняется. Скрипт создаёт задачу `SecretSanta-Web`, запускающую приложение после загрузки Windows от текущего пользователя с обычными правами, без сохранения пароля Windows. Параметр `-EnableTailscaleUnattended` также включает серверный режим Tailscale; без этого параметра настраивается только задача приложения. Если PowerShell запущен под другим администратором, передайте `-Account 'ИМЯ-PC\имя-пользователя'` организатора. Журнал настройки хранится в закрытом `data/setup/autostart.log`. Задача читает `data/hosting.json`; Funnel нужно включить отдельно. Для ручного запуска задачи используйте `Start-ScheduledTask -TaskName SecretSanta-Web`, предварительно остановив экземпляр сайта в терминале. Для удаления автозапуска — `Unregister-ScheduledTask -TaskName SecretSanta-Web`; серверный режим Tailscale отключается отдельно командой `tailscale set --unattended=false`.

Документация: https://tailscale.com/docs/features/tailscale-funnel , https://tailscale.com/docs/reference/tailscale-cli/funnel , https://tailscale.com/docs/how-to/run-unattended .

### Со своим доменом

Для домашнего компьютера подходит туннель: он направляет запросы с внешнего адреса на `http://localhost:3000`, без открытия входящего порта роутера. Например, [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/) с постоянным доменным именем. Для такого варианта нужен аккаунт Cloudflare и домен в нём; настройка выполняется на компьютере, где запущен сайт.

Выберите постоянный адрес до рассылки приглашений. Временный туннель со случайным именем подходит для проверки, но после смены адреса старые ссылки перестанут открываться. Сохранённые анкеты при этом остаются в `data`.

Укажите в туннеле локальную службу `http://localhost:3000`. Не публикуйте папку `data` через файловый сервер. Далее запустите приложение с точным внешним адресом, заменив `https://santa.example.com` своим реальным адресом.

**Windows PowerShell — в каждом терминале перед командами приложения:**

```powershell
$env:APP_URL = 'https://santa.example.com'
$env:NODE_ENV = 'production'
$env:HOST = '127.0.0.1'
$env:PORT = '3000'
npm.cmd start
```

Во втором терминале задайте те же переменные, затем выполните `npm.cmd run access` вместо `npm.cmd start`. Вызов `npm.cmd` не требует изменения политики выполнения PowerShell.

**macOS / Linux — в каждом терминале перед командами приложения:**

```sh
export APP_URL='https://santa.example.com'
export NODE_ENV=production
export HOST=127.0.0.1
export PORT=3000
npm start
```

Во втором терминале задайте те же переменные, затем выполните `npm run access` вместо `npm start`. Выполняйте команды из одной папки проекта, чтобы использовать одну папку `data`. Приложение само не загружает `.env`.

## 3. Проверить перед рассылкой

1. На телефоне выключите Wi-Fi и откройте внешний адрес через мобильный интернет. Главная страница должна загрузиться, а `/healthz` — вернуть `{"ok":true}`.
2. Войдите по ссылке организатора, создайте личное приглашение и откройте его в другом браузере. Проверьте портрет, сохранение пожеланий и статус готовности в кабинете организатора.
3. Отправьте каждому только его личное приглашение. Общую ссылку можно использовать для самостоятельного присоединения; ссылку организатора не отправляйте.

## 4. Оставить сайт работающим

Отключите сон компьютера на время работы сайта. Закрытие терминала или завершение сеанса может остановить приложение и туннель. Автозапуск обеих служб настраивается отдельно для выбранной ОС; одни только команды выше его не включают.

После перезагрузки запустите приложение и туннель с тем же внешним адресом и папкой `data`. Для резервной копии остановите приложение, скопируйте всю папку `data` в защищённое место и снова запустите сервер. В папке находятся личные данные и ключи доступа; её нельзя добавлять в публичный GitHub.
